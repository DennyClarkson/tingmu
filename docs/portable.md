# 听幕便携版

双击 `Tingmu.exe` 打开播放器。无需安装 Python，无需运行 CMD 或安装脚本。

在「工作区设置 → 文本模型与 API」或「队列 → 设置」可调整「高并发请求 LLM」。每个工作区默认最多同时发 4 个请求，可选 1–16。关闭后每次只发 1 个。原文复核、逐句讲解和译稿核验依次进行，每个阶段内同时处理多批字幕，结果按时间轴排列。改动在下个视频开始时生效，正在运行的视频可暂停后继续以采用新上限。

复核、讲解或译稿中有一句写错字段时，听幕先保存编号匹配且已通过校验的其他字幕，再把出错句、字段要求和附近台词发给模型修正。整个响应被截断或字幕编号对应关系混乱时，会拆小批次重新核对。多次仍未通过时，队列会显示能定位到的句序和时间码。点击「重试」后会读取已通过的结果和上次错误。

服务限流时可降低并发上限，按队列显示的建议等待时间再重试。密钥无效、余额不足或模型不可用时，队列会提示检查相应连接。

### 播放器与字幕

**准备讲解和翻译稿。** 在工作区选择已知语言与学习语言。新建时可勾选「沿用当前工作区的文本模型」，也可在「文本模型与 API」为逐句讲解分配本机或远程连接。准备视频后，听幕按源句生成已知语言的讲解与翻译，再由讲解模型单独对照原文和上下文核验译稿。长句拆为多条屏幕字幕时，每段都有对应译文。关闭文本模型时只生成原文字幕。

已有字幕的视频可在伴侣或播放器的「字幕」页点「补全讲解与译稿」。失败后重试可继续使用已保存的阶段结果。生成进度分别列出讲解句数和复核句数。播放时可独立勾选「显示学习字幕」和「显示〈已知语言〉译文」，两项同时开启即为双语。完整译稿随学习文档存为 `documents/<材料编号>.translation.srt`，也可在文件菜单导出为易识别的片名与语言代码。

点击时间轴右下方的齿轮进入播放器设置。**声音**可选择系统默认输出、指定耳机或扬声器，也能切换片源音轨。设备断开后使用系统默认输出，已选设备重新连接时会恢复。

**字幕**中可以独立开关学习字幕、影片内嵌轨和导入的播放字幕。打开多项时会同时显示。导入支持 SRT、VTT、ASS 和 SSA，字幕按视频存在当前工作区的 `playback-subtitles/`，再次打开视频可继续使用。要用字幕建立或替换学习文档，请使用文件菜单中的「从字幕建立学习文档」。

在**样式**里可预览字体、颜色、描边、阴影、底框和九宫格位置，也可命名保存。文字字幕共用当前工作区的样式，图像字幕保留片源字形，其大小和垂直位置可在**字幕**页调整。**控制栏**可以选择显示剩余时间、A–B 循环和自动隐藏时长。「为下方控制栏预留空间」默认开启，全屏时画面和字幕都在下栏上方。

## 0.7 用对话开始学习

打开「对话」，输入「我要学英语了」。听幕会查找相同语言组合的工作区，需要时新建，然后检测本机的识别运行时、显卡、内存、剩余磁盘和已安装模型。这个简单的开工指令也可以在尚未配置文本模型时使用。连接对话模型后，可以进一步说明「我想用普通话学英语，建一个美剧听力工作区，优先识别准确度，沿用我的讲解模型」。

已安装的识别模型直接复用。缺少权重时，界面列出目标工作区、模型和预计下载量；在原对话输入「同意下载」或点击同名按钮，即可下载到应用的共享模型目录。关闭再打开软件后，未确认的下载需要重新提出。应用也能按你的要求绑定正在运行的本机 Ollama、LM Studio 或转写 API。远程文本连接可单独确认沿用，外部转写的音轨发送权限仍由工作区的语音设置控制。

两种语言可自由组合，也可以相同。例如「我要用斯瓦希里语学冰岛语」或「用 pt-BR 学 x-example」。设置里的语言名称来自 Unicode CLDR，也能直接填写其他语言代码。若内置识别模型不支持目标语言，可把配套字幕与视频一起放进工作区，或配置支持该语言的转写 API。

进入工作区后，点「工作区设置 → 语言与文件 → 打开视频目录」，把视频放进去。当前工作区会在复制完成且识别方式可用后自动加入准备队列。同一页可以调整「自动准备放入 media 的视频」。语言笔记、字幕、讲解和播放记录保存在工作区内。

## 0.6 工作区与字幕

打开听幕会恢复上次使用的工作区。通过主界面顶部的工作区选择器，可以随时在已有工作区之间切换，或创建不同语言组合的新工作区。升级前的资料归入默认工作区。工作区中的 `media/` 可接收导入的视频，`documents/` 保存 SRT 字幕和 JSON 逐句讲解，`notebooks/` 保存 Markdown 笔记。共享模型缓存位于应用的 `.cache/`。

在「工作区设置 → 语音识别」可使用内置 Whisper/Qwen、已有本机 Whisper 模型目录、本机语音 API 或远程语音 API。本机服务可使用免密或受认证的回环连接。到「文本模型与 API」可停用文本模型、仅使用本机 API，或启用远程 API，并独立指定复核、讲解、对话模型。自建工作区位于 `data/workspaces/`；导出文件保存到当前工作区的 `exports/`。

在学习伴侣或主界面的字幕行使用「纠正此句」，说明确认的字词或含义后点「复核并保存」。原始转写、原始时间和备份均保留。字幕生成默认在本机先分离人声并检测换人。重叠对话、短插话的切分效果取决于音轨和对齐结果。工作区也可选择 CPU 识别或外部转写接口；选择外部服务后需要另行允许发送所选音轨。[外部接口说明](https://developers.openai.com/api/docs/guides/speech-to-text)

## 0.5 使用入口

顶部「观看 / 准备 / 学习」切换当前学习工作区的视图。「准备」队列勾选视频后可清除识别与讲解，或仅重做讲解；确认框可同时重新排队。视频及个人收藏、笔记、进度保留，当前材料清除前备份在工作区的 `material-backups/`。

「学习」按所学语种管理 `data/notebooks/<语言>/notebook.md`。观看时先收集到「收藏」，点击整理或让 Agent 整理后才写入「笔记」；原收藏保留并标记已整理。笔记按主题组织，支持语法、母语对比、例句、目标和词句个性化备注，可编辑与导出，来源可跳回视频。AI 整理保留手写内容，「复习」可自评掌握程度。全屏暂停时可拖选字幕原文、点词或收藏整句，再进入学习工作区。

「对话」支持多会话、Markdown、表格、代码复制、流式回复、停止、编辑和重试。编辑和重试另建会话分支，原回答保留，并沿用发起时的视频、语种、模型和思考强度。输入框下可选择思考强度；不支持的选项会说明原因，可改为「默认」。Agent 可处理视频和队列、操作播放、整理收藏、修改保存笔记及备注、调整主题和已有模型。工具执行状态会显示在对话里。保存「讲解更详细」等偏好仅用于后续生成，明确要求重做时才重新处理已有材料。不支持原生工具的服务使用受限 JSON 规划兼容流程，再流式生成回答。不会执行任意系统命令。

模块浮出后会释放主窗口原位置；通过「工作区」菜单可重新打开或放回。点击全屏后可直接用空格暂停/继续，Esc 退出；编辑输入框时仍可正常输入空格。

「工作区 → 模型管理」添加模型连接，也可从队列/聊天齿轮进入。选择服务预设，填写地址和凭据；模型 ID 可先留空，保存后「加载列表」，再选择并保存。复核、讲解和对话分别指定模型。手工密钥由 Windows DPAPI 加密，不会明文写入配置或日志；换电脑或 Windows 账号后需重新输入。也可只使用环境变量。

顶栏可选森林、纸页、雾青、石墨主题。思源黑体、思源宋体、Source Sans 3、Source Code Pro 字体及开源许可均在应用内，无需另行安装字体。

新版界面使用 Qt Quick / QML，Python 继续负责本地播放器、识别、字幕与学习数据。Qt Quick 和多媒体插件已包含在现有运行时中，无需额外安装浏览器或下载另一套运行环境。应用入口仍为同一个 `Tingmu.exe`。

请整体保留、复制或移动 `Tingmu` 文件夹，不能单独取出 EXE。文件夹可改名，也可放到其他有足够空间且允许写入的磁盘位置。不要放进只读目录或 `Program Files`。关闭听幕后再搬迁或备份。

- `data/`：设置、学习材料、生词、笔记、复盘、聊天、播放记录及本地日志。
- `.cache/`：离线语音模型、运行缓存和临时文件。
- `runtime/`：随附 Python、PySide6、CUDA/ASR 依赖；不是指向开发环境的快捷方式。
- `bin/`：随附 FFmpeg 与 FFprobe；`app/`：应用程序。

本次便携文件夹已复制旧版 `%LOCALAPPDATA%/Tingmu` 数据，原目录保留不动。数据库通过 SQLite 在线备份复制；复制记录在 `data/import-manifest.json`。旧数据中的视频路径仍指向原视频，移动软件不会搬动视频；视频另行移动后请重新打开对应文件。

`examples/` 中的三段视频与已准备学习材料可以随便携目录一起移动。启动时根据 `data/portable-location.json` 更新内部媒体对应的学习材料、笔记、聊天、播放位置、队列和设置路径；目录外的视频引用保持原样。迁移前的数据库和 JSON 原件保留在 `data/migration-backups/`。如发现目标材料或记录冲突，会明确停止迁移并保留两份数据，不会静默覆盖。

默认在本机处理音视频。已缓存 Qwen3-ASR 1.7B、强制对齐模型及 Whisper turbo。Qwen 使用随包 CUDA 12.8 / PyTorch 2.7.1；GPU 加速仍需机器已有兼容 NVIDIA 驱动。CPU 可用，但速度和内存需求不同。Windows 10/11 x64、系统自带 .NET Framework 4.x；其他系统未验证。云端文本功能需要网络和已配置的凭据；手工密钥仅以本机保护的加密形式随数据保存。

启动错误详情在 `data/logs/application.log`。此便携包包含私人学习记录，分享前应另行准备空数据发行包。

在「帮助 → 开发者模式」开启诊断，再点「查看日志」，可以查看运行环境、模型配置、播放器与队列状态及近期日志，并导出诊断文件到 `data/diagnostics/`。普通模式记录 INFO 事件，开启开发者模式后增加 DEBUG 操作事件。`data/logs/events.jsonl` 每份约 2 MiB，保留 3 份轮转备份；启动日志 `application.log` 每份约 2 MiB，保留 2 份备份。日志不主动记录字幕、聊天、笔记或请求正文，已知 API 密钥会脱敏；异常记录保留类型和代码位置。

## 开发者构建与验证

在项目环境及 Qwen 模型就绪后运行 `scripts/build_portable.ps1 -ImportUserData`，生成忽略目录 `dist/Tingmu`。仅更新应用时使用 `-RefreshApp`；不会覆盖已复制的学习数据。不需要下载构建工具，Windows .NET 编译器生成原生窗口式 EXE 启动器。

`-RefreshApp` 同时更新 `app/tingmu/quick/qml/` 界面文件并检查随包 Qt Quick、Basic 控件、布局和多媒体模块及 DLL，不重复复制模型、Python 或 CUDA。启动器源码变化时会重新编译 EXE，因此刷新前需关闭应用。独立进程名 `TingmuRuntime.exe` 避免 Windows 把播放器与 Python IDLE 混为同一个应用。`tingmu-portable.json` 记录 QML 文件哈希与所需插件；缺少文件时构建会失败。启动器覆盖外部 QML/Qt 插件搜索路径，QML 编译缓存和 Qt 着色器缓存分别写入 `.cache/qml` 与 `.cache/qt-shaders`。

打包采用随附 CPython 与相对 `python312._pth` 隔离搜索路径，应用和 ASR 分别使用各自依赖环境。构建不复制开发缓存归档、下载分片或重复模型 blobs，仅复制可离线解析的 snapshot 文件和 refs。此选择依据 [Python Windows 嵌入与隔离说明](https://docs.python.org/3/using/windows.html#finding-modules)；相比 [PyInstaller 单目录打包](https://pyinstaller.org/en/stable/operating-mode.html)，保留完整 Python 包布局便于 Qt 与 ASR 的动态依赖加载。

随包 Nagisa 0.2.11 的 DyNet 模型读取做了一处构建时兼容修补：使用 Python 切换到模型目录，再用原始 ASCII 文件名加载，最后恢复目录。修补只作用于随包依赖，不改权重、分词逻辑或开发环境；解决 [上游已报告的 Windows 非 ASCII 路径失败](https://github.com/QwenLM/Qwen3-ASR/issues/214)。加载发生在独立 ASR 子进程内。

`Tingmu.exe --portable-smoke` 会短暂启动真正的 QML 界面并写入 `data/logs/portable-smoke.json`，测试学习数据使用独立的 `.cache/portable-smoke/<随机编号>/data`，不改日常学习资料。附加 `--smoke-media 视频绝对路径` 可检查实际视频帧、定位、倍速、多音轨切换及暂停。自动化可设置进程环境 `QT_QPA_PLATFORM=offscreen` 检查窗口构造而不占用桌面；离屏通过不等同于屏幕目视验收。诊断用途的解释器在 `runtime/python/python.exe`，不是用户日常入口。

## 本机验证（2026-11-14）

0.3.0 Qt Quick 界面已从随包 `Tingmu.exe` 实际启动：最终离屏与 Windows 原生窗口分别解码 51、54 帧，定位、1.25 倍速、两条音轨切换及暂停全部通过，无播放器或 QML 警告。原生窗口截图确认视频实际显示。诊断数据使用独立目录；刷新前后 39 个既有非日志数据文件的 SHA256、40,815 个运行时文件的大小/时间清单以及 EXE 哈希均保持一致。QML 源码、图标和样式一并包含在发行清单中。

以下是原有便携运行时的搬迁与离线识别验证；本次界面更新复用这套运行时：

- 整个目录改名为含中文和空格的路径后，EXE 离屏启动、窗口构造、配置与数据路径检查通过；刻意设置错误的 Python 和 C 盘缓存环境变量仍能启动。Python 模块路径全部落在移动后的便携目录。
- 改名目录中，离线 Qwen CUDA 实际识别 10 秒粤语视频，输出 4 句，含模型加载用时 34.128 秒，无对齐错误。不是准确率评估。
- 随包 Qt 对原样片实际解码 70 帧，并验证两条音轨、定位、1.25 倍速、音轨切换、暂停，全部通过。
- Python 3.12.14、Qt 6.12.0、FFmpeg 9.0、Qwen-ASR 0.0.6、PyTorch 2.7.1+cu128。初始完整目录约 17.29 GiB；模型、CUDA 库和两套依赖占大部分，未保留重复模型下载分片。无指向开发环境的文件链接。

这些结果来自本机 Windows 及 RTX 5070 Ti Laptop GPU；未在没有开发环境的第二台电脑上测试。新电脑仍需兼容 Windows 与 NVIDIA 驱动。
